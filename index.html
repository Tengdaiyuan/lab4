Databases start with well-formed data.

This site holds both lab tasks. Task 1 is an XML book catalogue (book.xml); Task 2 is a JSON set of user profiles (userProfiles.json). Each page fetches its data file in the browser, parses it with the DOMParser / Response.json() APIs from the handout, and renders the records as cards and tables.

The two lab tasks

Both pages work directly on GitHub Pages — no build step, no dependencies.

1 · XML first

A catalogue of books. Every <book> has a unique id attribute and exactly the child elements <title>, <author> and <price>. It is served as text/xml and parsed with DOMParser.

books.html book.xml

2 · JSON second

Four user profiles, each with firstName, lastName, email, dateOfBirth, a nested address (street, city, state, zipCode) and preferences (theme, language, notifications, subscription).

users.html userProfiles.json

3 · Validation

The XML is checked for well-formedness by tools/validate.mjs (and by the browser parser itself). The JSON is machine-validated for structure and required fields. Both files also pass the online validators named in the handout.

How the data flow works

The same three steps on both pages.

// 1. fetch the data file that sits next to this page
fetch('book.xml')
  .then(response => {
    if (!response.ok) throw new Error('Fetch error: ' + response.status)
    return response.text()          // .json() for the JSON lab
  })
  // 2. parse it
  .then(xmlText => {
    const parser  = new DOMParser()
    const xmlDoc  = parser.parseFromString(xmlText, 'text/xml')
    const books   = xmlDoc.getElementsByTagName('book')
  })
  // 3. render it
  .then(render)
  .catch(err => console.error('Fetch error: ' + err.message))

Running locally? Browsers block fetch() on file:// URLs (CORS), so open the folder through a tiny local server: npm run serve (or node serve.mjs) and visit http://127.0.0.1:5173/. On GitHub Pages the same files are served over HTTPS, so the pages just work.
